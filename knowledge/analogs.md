# Аналоги и альтернативы

Статус: рабочая подборка для последующего исследования. Раздел выделен из [контекст-пака MTS, версия 2](../MTS/deliverables/context-pack.md#5-аналоги). Утверждения из командных набросков требуют сверки с первоисточниками; сопоставимость решений с предполагаемым продуктом не установлена.

По материалам MTS известны два текущих способа решать задачу; их стоимость и качество не измерены в сравнении.

| Альтернатива | Что знаем | Что сравнивать с нашим предложением |
| --- | --- | --- |
| Ручное ревью аналитиком и разработчиком | Действующий процесс по S-02, абзацы о ревью | Значимые находки и пропуски, время участников, последующие доработки |
| Внутренние LLM через веб-интерфейс | Доступны; респондент описывает недостаток контекста и формальные замечания — S-06, E-11, E-12 | На одинаковых документах проверить полезность, пропуски и полное время применения результата |

Для последующего исследования: проверить, какие инструменты умеют ревью требований и документации, как используют контекст клиента, объясняют замечания и встраиваются в среду заказчика. Утверждения об уникальности, превосходстве и отсутствии аналогов пока не обоснованы. Сравнение нужно также с простым базовым вариантом LLM-проверки без дополнительного контекста — [план проверки, раздел 3](discovery-plan.md#3-подготовить-проверку-решения).

## Кандидаты из командных набросков

Источник: [S-07b, актуальные дополнения раздела «Аналоги»](https://github.com/DanilaSaraev-git/ai-review-product/blob/259b0663f55d743a6f44d5e46cf7f1d9c3c1fddf/CONTEXT_PACK_MTS.md). Сохранены последние описания и ссылки команды; прежняя подборка S-07a остаётся в истории Git. **Статус описаний наброска: не проверены как целое.** Отдельные возможности Spec Kit и QVscribe сверены в [обзоре проверок требований](requirements-workflow-evidence.md); это не подтверждает все утверждения списка или применимость к кейсу MTS.

### 1. Альфа (Alfa Desmond)

Триггер: вебхук из Jira при смене статуса задачи.
Пайплайн: парсинг HTML из Confluence → нарезка текста на чанки с перекрытием → параллельная проверка в LLM по «машинному» стандарту → склейка ответов и постинг отчёта комментарием в Jira.

[Ссылка из наброска](https://habr.com/ru/companies/alfa/articles/932058/)

### 2. Сбер

Сбер даёт API GigaChat и активно продвигает агентную архитектуру на LangGraph. Прямого продукта для ревью ТЗ нет, но есть готовый фреймворк для построения мультиагентных систем анализа документов. Аналитик загружает ТЗ в систему, и ИИ сверяет его с базой знаний внутренних ГОСТов и архитектурных комитетов

[Ссылка из наброска](https://habr.com/ru/companies/sberbank/articles/941340/?ysclid=mtlh6s3y3i846089481)

### 3. Ростелеком (RT.DataGovernance)

Архитектура строится вокруг RAG‑пайплайна:  документ разбивают на смысловые чанки и переводят в векторные представления, затем по ним ищут релевантные корпоративные стандарты и примеры удачных формулировок. LLM сопоставляет фрагменты ТЗ с базой знаний и по жёсткому промпту выделяет неоднозначности, пробелы и потенциальные риски для разработчиков. Результат возвращается в JSON с пометками по разделам, цитатами и рекомендациями.

[Ссылка из наброска](https://habr.com/ru/companies/rostelecom/articles/994860/?ysclid=mtldf8qml675093844)

### 4. AI Engineering Control

Продукт для инженерного контроля рабочей документации. Находит противоречия между чертежами, спецификациями, ведомостями и исходными требованиями. Формирует ведомость замечаний с привязкой к документу, странице PDF и листу.

[Ссылка из наброска](https://ai-econtrol.ru/)

### 5. AllSee

AI-система на базе RAG и LLM, которая сверяет проектную документацию с актуальной базой нормативов. Система находит нарушения и формирует отчёт с точными ссылками на нарушенные пункты.

[Ссылка из наброска](https://allsee.team/services/avtomatizaciya/proverka-po-gostam)

### 6. Топливная компания росатома "ТВЭЛ"

Обучаемая NLP-модель, OCR-модуль для извлечения текста из рисунков и графических схем

[Ссылка из наброска](https://globalcio.ru/projects/27936/?ysclid=mtleal201n351619081)

### 7. НЛМК

LLM развёрнуты во внутреннем контуре (модели не раскрывают

[Ссылка из наброска](https://habr.com/ru/companies/nlmk/articles/989166/?ysclid=mtlhcdnp3m602445140)

### 8. Нормикс

Российский продукт, который проверяет проектную документацию на соответствие нормам и на противоречия между разделами — с конкретными ссылками на пункты нормативов.

[Ссылка из наброска](https://normix.ai/)

### 9. GitHub Spec Kit — spec-driven development с маркерами неоднозначности

ИИ не просто проверяет готовый документ один раз, а работает как непрерывный партнёр на протяжении всего процесса написания спецификации, задавая вопросы и помечая проблемные места. ИИ-агент подключается как "соавтор" и задаёт уточняющие вопросы по мере написания, выявляет edge cases

### 10. StoryPromptAnalyzer — интеграция с Jira.

Сервис, который конвертирует Jira user stories в структурированные AI-промпты и генерирует отчёты с анализом неоднозначностей и пробелов. Три режима: Single Story (анализ одной истории), Sprint Analysis (консолидированный отчёт), Blaze Rules Context Mode (поиск по кодбазе).
Вывод: Quick Summary → Ambiguities → Critical Gaps → Risks → Recommendations

[Ссылка из наброска](https://github.com/mac50503/StoryPromptAnalyzer?ysclid=mtlfosoj2j850485263)

### 11. ReqSpell (SoftSpell)

Платформа использует NLP и машинное обучение, чтобы анализировать требования. Находит неоднозначные формулировки, выявляет пробелы, а также обнаруживает дубликаты и противоречия между разными частями документа.

[Ссылка из наброска](https://www.softspell.ai/blog/ai-requirements-management-reqspell)

### 12. QRA QVscribe + ReqWriter

QVscribe анализирует каждое требование в реальном времени, а ReqWriter предлагает переформулировки. NLP-движок, основанный на правилах INCOSE и нотации EARS,
Real-time анализ прямо в процессе написания — не после, а во время

[Ссылка из наброска](https://qracorp.com/)

### 13. Mockitt AI Requirements Review

Три категории проверок:
Multi-Perspective — сканирование с разных точек зрения: техническая осуществимость, edge cases, пользовательский опыт
Edge Case Detection — ИИ автоматически задаёт вопросы вида: «Что отобразится при отключении сети? Что если данные пустые?»
Ambiguity Resolution — находит неквантифицируемые термины и предлагает конвертировать их в измеримые метрики

[Ссылка из наброска](https://edge.mockitt.com/en/ad/aireview)
