# Концепт веб-интерфейса AI Review

Статус: визуальный прототип для обсуждения, не реализация продукта и не подтверждение продуктовых гипотез.

Макет использует обезличенные материалы кейса MTS, поэтому хранится внутри `MTS/`. Общая визуальная рамка остаётся нейтральной: MTS отображается как выбранный клиентский профиль, а не как бренд продукта.

## Проверяемые вопросы

- Подходит ли аналитику плотный классический интерфейс с красным акцентом, в котором подготовка ревью отделяет основной документ от профиля и явно подключённых контекстных артефактов?
- Помогает ли постоянная связь «фрагмент документа ↔ замечание ↔ решение аналитика» быстрее разобрать результат ревью?
- Нужен ли адаптивный диалог по одному выбранному замечанию после обычного ревью?

## Экраны сценария

- [`01-new-review.svg`](01-new-review.svg) — векторный исходник экрана создания ревью с открытой панелью контекста.
- `01-new-review.png` — растровый экспорт для просмотра после визуальной проверки.
- [`02-review-results.svg`](02-review-results.svg) — рабочее место ревью: документ, связанные подсветки и панель замечаний.
- `02-review-results.png` — растровый экспорт экрана результата.
- [`03-finding-dialog.svg`](03-finding-dialog.svg) — диалог с агентом по выбранному замечанию `F-003`.
- `03-finding-dialog.png` — растровый экспорт экрана диалога.

Три экрана образуют один статический сценарий: подготовка запуска → результат обычного ревью → допрос по одному выбранному замечанию. Переходы и элементы управления пока не реализованы.

## Зафиксированные решения макета

- рабочее название продукта — `AI Review`;
- desktop-артборд — 1440 × 900;
- красный используется как брендовый акцент, крупные поверхности остаются нейтральными;
- до запуска показывается технический статус `AI-ревью: не запущено`;
- после запуска показывается предварительный `Статус AI-ревью`, а не экспертное одобрение документа;
- профильные материалы отделены от временных материалов запуска;
- исходный документ не редактируется внутри интерфейса;
- правая панель сохраняет геометрию при переходе от списка замечаний к диалогу;
- диалог открывается из конкретного замечания и не превращает чат в основной объект интерфейса;
- неподтверждённые наблюдения выключены по умолчанию и не смешиваются с правилами команды.

Данные интерфейса основаны на существующих файлах `MTS/`. Для экранов 2–3 использован производный рендер страницы 5 исходного PDF: [`assets/test-data-page-05.png`](assets/test-data-page-05.png). Оригинал PDF остаётся первичным источником; растровый файл нужен только как подложка статического макета.

Формулировка `F-003` отражает текущего кандидата на замечание о семантике часового сдвига. Ответ аналитика и последующий вопрос агента на экране 3 — иллюстративные реплики, а не факты MTS. Сам режим допроса, вычисление общего статуса и все подписи элементов управления являются проектными гипотезами и требуют проверки с пользователем.
