## Что требуется для профиля подключения

Для каждого кандидата пока неизвестны: точный model ID/checkpoint и версия; квантование; serving/формат API и точный endpoint; фактический context window и допустимый вход с резервом ответа; параметры reasoning/sampling; поддержка JSON/JSON Schema; credentials и доступность. Значения из карточки модели не становятся автоматически настройками конкретного endpoint.

Сначала подтвердить идентичность и deployment-настройки, затем выполнить opt-in compatibility suite. До этого статус endpoint — unverified. Список не является сравнением качества, решением о победителе или свидетельством продуктового эффекта.

Маршрут сохраняется: внешний API при разработке → API в контуре заказчика. Конкретная модель и внешний провайдер обсуждаются в исходной задаче и ещё не выбраны. [Инженерный слой 004](../specs/004-llm-review-integration/plan.md) остаётся нейтральным; его обязательные тесты используют синтетический провайдер. Клиентские документы внешнему API при этом обновлении не отправлялись.
