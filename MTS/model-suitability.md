# Предварительная оценка моделей для ревью ТЗ

Дата: 2026-09-05. Статус: исследование первичных источников и гипотезы пригодности; модель и провайдер не выбраны, вызовы моделей не проводились.

## Основание и границы

Пользователь передал 05.09.2026 сообщение о моделях заказчика: «Qwen 2.5. - 32B. Kimi - K2. Deepseek R1 14B.» Это клиентское свидетельство, а не проверенный каталог API. Полные идентификаторы, версии, квантование и настройки сервера неизвестны. Рабочие соответствия: `Qwen/Qwen2.5-32B-Instruct`, `moonshotai/Kimi-K2-Instruct`, `deepseek-ai/DeepSeek-R1-Distill-Qwen-14B`; каждое требует подтверждения. Kimi K2 нельзя автоматически заменять K2.5/K2.6, Thinking или обновлённым Instruct.

Задача по [контексту MTS](README.md#ожидаемый-результат-и-границы): находить неоднозначности, пробелы и несогласованности в русскоязычных ТЗ на потоки и витрины данных, приводить фрагмент и вопрос аналитику. В обсуждаемом решении также нужен диалог по замечанию с учётом дополнительного контекста; окончательное решение принимает человек.

## Факты из карточек авторов

| Кандидат | Подтверждённые характеристики и ограничения источника |
| --- | --- |
| Qwen2.5-32B-Instruct | 32,5 млрд параметров. Авторы заявляют поддержку русского языка, улучшения следования инструкциям, понимания таблиц и генерации JSON. Это заявления разработчика, а не результаты нашего теста. Конфигурация по умолчанию рассчитана на 32 768 токенов; до 131 072 — с расширением YaRN. Заявленная длина генерации — 8192 токена. Источник: [карточка Qwen, Introduction / Processing Long Texts](https://huggingface.co/Qwen/Qwen2.5-32B-Instruct). |

Есть оценка следования инструкциям IFEval, но она не измеряет наше ревью и соблюдение нашего JSON-контракта. Рекомендована температура 0,6, пример использует system prompt. Рекомендации семейства: температура 0,5–0,7, инструкции в user prompt без system prompt, учёт формата `<think>`. Источник: [карточка DeepSeek, Distilled Model Evaluation / Usage Recommendations / License](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-14B). В [конфигурации 14B](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-14B/blob/main/config.json) `max_position_embeddings=131072`; это не подтверждает такой лимит у заказчика. |

Во всех случаях фактический бюджет API надо проверять отдельно: инструкции, ТЗ, контекст и ответ должны помещаться вместе. Размер окна не доказывает одинаковое качество обработки всех его частей. В просмотренных источниках нет измерений ревью русскоязычных ТЗ MTS. Отдельное качество русского языка и возможное смешение языков у Kimi и Distill-14B здесь не установлены; отсутствие такой оценки не означает неспособность отвечать по-русски.

## Пригодность для задачи — гипотезы

**Qwen — обоснованный первый кандидат для базового сравнения.** Заявленные возможности непосредственно связаны с нашими требованиями: таблицы полей, русское объяснение, компактный структурированный результат, диалог. Доказательств, что он уже достаточно точен или превосходит остальных на наших данных, нет.

**Kimi — полноценный кандидат для сравнения качества.** Общий диалог и следование инструкциям соответствуют сценарию, а логические задачи в авторской оценке дают основание проверить связи между разделами ТЗ. Большой общий размер не гарантирует более полезных замечаний. 32 млрд активных параметров не делают размещение эквивалентным Qwen-32B; при готовом API это инфраструктура провайдера или заказчика, а для продукта важны реальные задержка, лимиты и стоимость.

**DeepSeek 14B — кандидат для проверки достаточности меньшей модели.** Рассуждения могут помочь разобрать порядок фильтрации и преобразований. Но короткий JSON и управляемый диалог нужно проверять отдельно: формат размышлений и рекомендации по инструкциям требуют настройки адаптера. Меньший размер не гарантирует более быстрый ответ, если генерируется много промежуточного текста. Выделять этой модели постоянную роль второго ревьюера до эксперимента оснований нет.

## Минимальная проверка — предложение, не согласованный порог

1. Подтвердить точные checkpoints и ограничения API; зафиксировать одинаковые документы и содержательные инструкции, учитывая штатный формат запросов каждой модели.
2. Проверить три имеющихся примера и варианты с явно обозначенными искусственными изменениями. Например, [M-06](document-analysis.md#кандидаты-на-замечания) проверяет связь фильтра ненулевых LAC/CELL с последующими резервными правилами; M-08 — способность допустить совместимость инкремента с полной заменой месячной партиции. Эти наблюдения требуют эксперта и не являются эталоном.
3. Для каждого замечания оценивать обоснованность, полезность, точность цитаты, отсутствие выдуманных правил и дублей; для каждого ответа — соответствие JSON-схеме, русский язык, время и объём генерации. Некорректный формат и неверные цитаты учитывать как сбои, а не скрывать исправлением.
4. В диалоге дать пояснение, снимающее неоднозначность, и проверить пересмотр замечания без безусловного согласия с любым ответом. Повторить прогоны для оценки устойчивости.
5. После настройки проверить новый документ с независимой экспертной оценкой. На трёх уже разобранных примерах нельзя заявлять независимую точность, экономию времени или готовность к промышленной эксплуатации. Допустимая доля лишних замечаний и другие численные критерии пока не согласованы.
