# Research: технические решения PoC

Дата: 2026-09-03. Техническая разведка по официальным первичным источникам; это не сравнение качества обработчиков и не исследование спроса.

## PDF adapter

**Decision**: pdfplumber 0.11.10 по умолчанию за ParserAdapter; исходное представление страниц/таблиц сохраняется в raw. Версия закреплена вместе с транзитивными зависимостями.

**Rationale**: прямое поручение пользователя. Релиз 0.11.10 опубликован 15.06.2026 ([PyPI](https://pypi.org/project/pdfplumber/), [release](https://github.com/jsvine/pdfplumber/releases/tag/v0.11.10)). extract_text собирает текст из символов; layout=False и допуски 3 явно записываются. find_tables возвращает bbox и ячейки; table.extract сохраняет матрицу и различие null/пустой строки ([text](https://github.com/jsvine/pdfplumber#extracting-text), [tables](https://github.com/jsvine/pdfplumber#extracting-tables), [код Table](https://github.com/jsvine/pdfplumber/blob/v0.11.10/pdfplumber/table.py)).

**Alternatives considered**: Docling остаётся кандидатом отдельного сравнения; выбор пользователя не доказывает превосходство. OCR вне PoC; pdfplumber не предоставляет OCR ([ограничения](https://github.com/jsvine/pdfplumber#comparison-to-other-libraries)).

Наше решение: текст страницы плюс отдельные строки таблиц с координатами, без молчаливого склеивания имён полей и объединённых ячеек. Стратегия таблиц lines/lines — начальная настройка, не гарантия обнаружения всех таблиц. Пустая страница означает ограничение извлечения, а не доказанное отсутствие содержания.

## Reproducibility

**Decision**: неизменяемый снимок prepare, отдельный run-id; SHA-256 байтов источников и подготовленных файлов, явные настройки, версии Python/навыка/зависимостей; uv.lock.

**Rationale**: одного pin pdfplumber недостаточно — зависимости также влияют на извлечение ([requirements релиза](https://github.com/jsvine/pdfplumber/blob/v0.11.10/requirements.txt)). Адреса зависят от порядка источников и геометрии, их стабильность между версиями не обещается.

**Alternatives considered**: БД/объектное хранилище избыточны для локального PoC; хеш текста без оригинала скрывал бы изменение входа.

## Contract and evidence

**Decision**: JSON Schema для отчёта и профиля; дополнительные проверки ссылок, цитат, полного разбиения охвата и хешей. Цитаты нормализуются только NFC и пробелами. Для отсутствия требования scope перечисляет прочитанные фрагменты ТЗ.

**Rationale**: совпадение цитаты проверяемо программно, полезность вывода требует эксперта. Источник остаётся первичным, нормализованное извлечение производным.

**Alternatives considered**: свободный Markdown не обеспечивает проверяемого контракта; автоматические смысловые правила подменили бы агентный сценарий хрупкими эвристиками.

## Agent boundary and demo

**Decision**: модель не вызывается из Python. SKILL.md задаёт ревью и отчёт, run-demo использует только синтетические фиксированные замечания с generation.mode=demo_fixture. Клиентский прогон generation.mode=agent выполняется средой агента.

**Rationale**: соответствует выбранному harness; неизвестные модель/версия сохраняются как unknown. Инструкции в источниках — данные, не команды. Профиль определяет направления проверки, а не права агента.

**Alternatives considered**: SDK конкретного LLM-поставщика и ключи сделали бы установку непереносимой и вышли бы за согласованный PoC.

Блокирующих технических неизвестных нет. Неизвестны качество на новых документах, экспертная полезность, затраты аналитика и совместимость с другими моделями; это будущие проверки.
