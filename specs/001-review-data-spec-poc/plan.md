# Implementation Plan: PoC ревью ТЗ

**Branch**: `codex/001-review-data-spec-poc` | **Date**: 2026-09-03 | **Spec**: [spec.md](spec.md)

**Input**: [утверждённый план](../../implementation/poc/PLAN.md) и поручение пользователя реализовать PoC с pdfplumber по умолчанию.

## Summary

Переносимая папка Agent Skill с Python CLI: prepare → смысловое ревью средой агента → validate → render. Команда run-demo воспроизводит синтетический пример с заранее заданными замечаниями и не вызывает модель. Клиентский агентный прогон выполняется отдельно. Первичные результаты имеют schema_version: 1.

## Technical Context

**Language/Version**: Python 3.11+.

**Primary Dependencies**: pdfplumber 0.11.10, jsonschema 4.25.1; точные транзитивные версии в uv.lock.

**Storage**: локальная новая папка на запуск; JSON, Markdown, побайтовые копии оригиналов. БД и сервер отсутствуют.

**Testing**: pytest; синтетические PDF через reportlab; subprocess-тест CLI и установка копии в отдельное окружение.

**Target Platform**: локальная среда с Python, файлами и агентом. Фактически проверенные среды фиксируются в quickstart и протоколе, совместимость со всеми агентами не заявляется.

**Project Type**: переносимый Agent Skill + CLI; модель предоставляет среда агента.

**Performance Goals**: количественный SLO не установлен; длительность prepare фиксируется в manifest, время аналитика — отдельно при экспертной оценке.

**Constraints**: локальный текстовый PDF/MD/TXT, без OCR и сетевого чтения; оригиналы неизменны; ошибки и непрочитанные области явны. Переносимая папка не содержит клиентские материалы.

**Scale/Scope**: один документ и явно подключённые файлы на запуск. Распределённое ревью, большие корпуса и многопользовательская изоляция вне PoC.

## Design decisions

Узкий ParserAdapter возвращает собственные структуры страниц, текст и таблицы с bbox. Используем pdfplumber по прямому поручению; сравнение с Docling не является блокером и преимущество не установлено. MD/TXT читает отдельный адаптер UTF-8. Привязки стабильны при том же входе, порядке контекста, версии и настройках обработчика.

Манифест хранит SHA-256 исходников и подготовленных артефактов, версии зависимостей, Python/навыка, профиль, настройки, run-id, время подготовки. Проверяемые цитаты сравниваются после NFC и схлопывания пробелов; переносы внутри идентификаторов не «исправляются». Снимок является локальной проверкой целостности, не криптографической подписью против автора, меняющего и файлы, и манифест.

Ошибки первичного документа прекращают prepare до публикации папки. Недоступный/нечитаемый контекст записывается как unavailable; неполное извлечение отражается в охвате. Неполные и конфликтующие правила агент показывает как неопределённость. Валидатор проверяет структуры и привязки, но не делает смысловых выводов.

Отчёт проверяется перед render; охват вычисляется из перечисленных фрагментов, диагностик и недоступных источников. Markdown экранирует содержимое, включает все замечания, исходные адреса и ограничения. Отсутствие требования использует scope вместо цитаты. Human decision отделён от приоритета.

## Verification strategy

US1: оригинальные байты, таблицы/null/переносы, повторная адресация, пустые/битые файлы и диагностика.
US2: выдуманные цитаты, неверные ссылки/версии/run-id, отсутствие требования, неполный охват, тамперинг, пустой отчёт; ручной агентный сценарий с инструкцией внутри документа.
US3: независимые профили, относительные пути, пропавший контекст и конфликт правил; сохранность всех приоритетов.
US4: установка копии, CLI вне репозитория, клиентский прогон, ссылки, симлинк и ignore. Экспертное качество и экономия отдельно не измеряются.

Расширения Spec Kit отсутствуют: before/after hooks для specify, plan, tasks, implement пропущены по правилам навыков.
